Kade Ops Agent
Built by Eugenio Díaz

An internal agent that answers from company data, not from memory.

Kade Logistics is a fictional freight forwarder. The agent searches its policies and contracts, queries invoices in its ERP and opens helpdesk tickets. Every step is traced, with tokens, cost and latency.

Retrieval

The 8 documents are split by section and indexed with BM25, implemented in about 50 lines with no vector database. That is enough for a corpus this size. Hybrid search with embeddings is the next step when it grows.

Tools

search_documents, read_document, query_invoices (ERP) and create_ticket (helpdesk). Schemas are closed, and tool errors go back to the model as is_error results so it can recover.

Agent loop

A manual tool-use loop on the Anthropic Python SDK, capped at 8 steps. It handles refusals, max_tokens and pause_turn explicitly. On Opus and Sonnet, a declined request falls back server-side to another model.

Cost and speed

The demo runs on Haiku 5.5 because the evals showed it: the same pass rate as Opus 5.5 at about 1/24 of the cost per answer and roughly half the latency. Prompt caching covers the system prompt and tool definitions, and each call's usage is priced per model in the trace.

Guards

Rate limit per IP, a daily API budget, a 1,000-character question cap and an 8-step cap. Tickets are created only when the user asks for one. For a demo the limits live in memory; in production they would sit in Redis or the gateway.

Tests

pytest covers retrieval, tools, the agent loop with a fake client, the API guards and the grader. Evals run separately because they call the real model and cost money.
